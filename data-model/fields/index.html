Fields

A Field is an attribute of a Collection: a film’s title, its release_year, its poster. Each has a key, a Data type, which says what it stores, and an Interface, which says how editors edit it. A Field that stores a value has its own column in its Collection’s table.

The Fields page

Section titled “The Fields page”

A Collection’s Fields page lists its Fields in the order the Item view shows them, with their Field groups, each with its Label, its key, its Data type and its Interface, and badges for what sets it apart: System field, Required, Unique, Read only, Hidden. Opening one shows its settings in the inspector beside the list, on four tabs:

  • General: its key, Labels, Data type, default value and whether it’s read only, hidden or searchable; and, for a Relation, what it relates to.
  • Interface: its Interface and that Interface’s options, such as a Dropdown’s choices.
  • Validation: whether it’s required, nullable or unique, and the rules its Interface adds, such as a maximum length.
  • Conditions: its Field conditions.

Changes are kept in the inspector until saved, with its tick button; closing it with changes unsaved asks first. The list’s own changes, moving and resizing Fields, are saved at once; see Field layout.

Adding a Field

Section titled “Adding a Field”

Add field opens the Interface picker, where you choose how editors will edit the new Field: an Input, a Dropdown, an Image, a Many to Many’s Related Items. The inspector then opens on the new Field, with a Data type among those that Interface edits, and asks for its key. See Interfaces for the whole catalogue.

The Key is the Field’s identifier, in snake_case like a Collection key, such as release_year, of 50 characters at most, and can’t be a System field’s. It names the Field’s column and its property in the API, and can’t change once the Field is added. The new Field goes after the Collection’s last Field that isn’t a System field.

Labels

Section titled “Labels”

A Field has three Labels, each in as many languages as you like:

  • Name: what people see instead of its key, in the Item view, List view columns, filters and exports. Reelhouse’s title of films reads “Original title”.
  • Description: help shown with it in the Item view. The films’ slug says “Names the film in its address on the website.”
  • Placeholder: shown in its empty box in the Item view.

A User whose UI language has no Name sees the key as words: release_year reads “Release year”. The Data model section shows keys as they are.

System fields

Section titled “System fields”

Every Collection has five System fields, which Nexus keeps:

Field Holds
id The Item’s primary key: a UUID, an integer or a string, as its Collection was created with.
created_on When the Item was created, a timestamp the database stamps.
created_by The User who created it.
updated_on When it last changed.
updated_by The User who last changed it.

They can’t be deleted, nor their Data type, Interface or behaviour changed: they can only be given Labels, placed anywhere in the Item view, resized and hidden from it, and shown as List view columns. created_by and updated_by must be given with every write of an Item, which Nexus does itself, unless the Project settings say otherwise.

Data type and default value

Section titled “Data type and default value”

The Data type can change while the Collection holds no Item, into any other that an Interface edits. Once it holds Items, it can only widen into a type that keeps every value as it was: string into text, integer into bigint or decimal, bigint into decimal. See Data types.

The Default value is what new Items start with, both in the Item view and in the database, so that a row written without it outside Nexus takes it too. Reelhouse’s TV shows start “In production”. Relations and File and Image Fields have none.

Read only, hidden and searchable

Section titled “Read only, hidden and searchable”

On the General tab:

  • Read only: shown in the Item view, but not editable there, and refused by the API: its value is its default, or what it was.
  • Hidden: left out of the Item view. It still takes values through the API.
  • Searchable: the List view’s search box looks in it; only text and number Fields of the Collection’s own table may be. See Searchable fields.

A Field that needs a value, as it’s required or not nullable, but is read only or hidden needs a default value, since no editor can give it one.

These shape the Item view for everyone. To keep a Field from a Role, or let it read but not write it, use Field permissions; to switch these states as the Item changes, use Field conditions.

Validation

Section titled “Validation”

On the Validation tab, for a Field that stores a value:

  • Required: editors must give it a value; Nexus refuses to save an Item without one.
  • Nullable: the database accepts Items without a value. Off, the column refuses to be empty, whoever writes it.
  • Unique: no two Items may share a value, which the database enforces. Reelhouse’s films’ slug is unique, so no two films have the same address on the website. For values that must differ only together, use a Unique set.

Below them come the rules the Interface adds for its Data type: a maximum length, a minimum and a maximum, a number of decimals, the largest file. Making a Field required, not nullable or unique is refused while Items stand in the way, which Nexus lists so that they can be fixed first.

Duplicating a Field

Section titled “Duplicating a Field”

The copy button at the top of the inspector duplicates a Field, into the same Collection or another, under a new key and in the group of your choice, with its Labels, Interface, options and conditions. Conditions that test Fields the target Collection lacks are left out, and the dialog says how many.

Deleting a Field

Section titled “Deleting a Field”

The bin at the top of the inspector deletes a Field, once its key is typed to confirm. Its column is dropped with the value every Item has in it, and so are the Unique sets it belongs to. A Many to Many’s or Many to Any’s Junction collection goes with it, with the values its links have. It can’t be undone.

A Field can’t be deleted while something else depends on it. Nexus says what, so that it can be changed first:

  • a Field condition of another Field, or of a Field group, that tests it;
  • the Collection’s Preview URL, or a Notice or a Button, whose placeholders fill it in;
  • a One to Many that inverts it, when it’s a Many to One;
  • the Project settings, when it’s a Field they designate of the Content languages collection.
