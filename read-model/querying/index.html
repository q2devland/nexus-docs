Querying

A client reads the Read model through the API, at /api/content, as any User or API user with its API token, or straight from the database with the nexus-content client, which answers the same for the same query. Reelhouse’s website build reads it as its API user, Website build.

Through the API

Section titled “Through the API”
  • GET /api/content answers a page of entries, the query in its parameters.
  • POST /api/content/query answers the same, the whole query as its JSON body: for a filter too long for a URL, or simply easier to write.
  • GET /api/content/<id> answers one entry by its id, such as films-2, with language and include as parameters; a 404 when there’s none.

It answers only the entries of the Collections the caller’s Role can read, every one for an Admin role; a Relation to a Collection it can’t read stays as ids, never loaded. No Extension hook runs: entries are read as they’re held.

The films released since 2022, latest first, in English, counted:

As a GET, the same query is ?collection=films&language=en&filter=…&sort=-release_year&count=true, filter and include as JSON, encoded for the URL, and sort as its paths separated by commas.

The query

Section titled “The query”
Part What
collection Only the entries of the Collection of that key; those of every Collection when left out
language The code of the Content language to read them in; see Language
filter Only the entries that pass it; see Filtering and sorting
sort Their order; see Filtering and sorting
limit How many entries to answer, 1 to 1,000; 100 when left out
offset How many to skip first, in their order; none when left out
count true to answer total too, how many entries pass the filter in all
include The related entries to load in place of their ids; see Including relations

It answers { "data": [...] }, a page of entries, with total when counted.

Filtering and sorting

Section titled “Filtering and sorting”

filter is written in the language of Nexus’s filters of Items, described in Filtering and sorting: a test of a path with an operator and a value, or a group of filters, and or or, nested. The Read model takes it with these limits:

  • A path takes one step: an entry’s own id, collection or updated_on, or a Field its Collection marks to sort and filter by, by its Query key, a translated one in the language read. No path goes through a Relation: a Many to One is filtered by the id of the entry it leads to, and a One to Many, Many to Many or Many to Any by the ids of the entries it links, as below. Filtering by the linked entries’ Fields, ["genres", "slug"], is refused.
  • A Field that isn’t marked is refused, even if the entry holds it: Reelhouse’s films can’t be filtered by runtime.
  • Without collection, a Query key is that of every Collection that marks a Field by it: the entries of the others hold none. Reelhouse’s genres and people both mark name, so the entries whose name starts with S are Science fiction and Sebastián Thornquist.
  • A Field given another Query key is named by it alone: Reelhouse’s TV shows are filtered by release_year, and start_year is refused.
  • At most 50 tests, groups 10 deep, 100 values in a list.

Texts are compared whatever their case and accents, unless the test says "sensitive": true. The Spanish titles of the films starting La , in Spanish:

answers La cartógrafa de Lumen Bay, La herencia de la marisma and La paloma dorada.

By a many-relation

Section titled “By a many-relation”

A One to Many, Many to Many or Many to Any takes contains-any, which holds for an entry that links any of the entries given, contains-all, for one that links all of them, empty, for one that links none, and not-empty. Its value is a list of 1 to 100 composite ids of entries of the Collections it leads to, such as genres-1; a bare id, 1, or another Collection’s, is refused. It tests the entries a Relation links even when it holds its links: Reelhouse’s cast holds films_cast links, and is filtered by the people they link. Reelhouse’s dramas, the latest first:

answers The Saltmarsh Inheritance, Paper Comets, Nine Winters in Hallow Creek, A Quiet Arithmetic and Kites over Karsk; with contains-all and ["genres-1", "genres-6"], the dramas that are romances too, Nine Winters in Hallow Creek and Kites over Karsk; and { "path": ["cast"], "operator": "contains-any", "value": ["people-7"] }, the films Greta Solberg-Hale plays in. Entries aren’t sorted by a many-relation: a sort that names one is refused.

sort lists the same paths but many-relations, at most 10, each descending after a -, such as ["-updated_on", "title"]; entries without a value come last, then entries are ordered by id. Left out, they come in the order of their ids, as text: films-10 comes before films-2. A client that reads what changed lately sorts by -updated_on.

Across Collections

Section titled “Across Collections”

Fields of several Collections that share a Query key are sorted and filtered together, from one column, whatever their own keys. Reelhouse’s TV shows sort their start_year by release_year, as films do theirs, so the films and TV shows that came out since 2022, the latest first:

answers both, interleaved by year. Each entry still holds its own Fields at their own keys: a TV show’s year is at start_year.

Paging and counting

Section titled “Paging and counting”

limit and offset read entries a page at a time, in their order: sort them, so that a page holds the same ones whenever it’s read. Counting them all costs a query of its own: ask for count on the first page alone.

Language

Section titled “Language”

A Project with Content languages reads every entry in one: language is needed, the code of one of them, and the entries’ translated Fields are those of that language. Reelhouse’s are en and es. A Project without any refuses one.

What it refuses

Section titled “What it refuses”

A query not shaped as one, or naming what the Read model doesn’t hold, is refused with a 400 saying what and where:

code When
invalid-language No language where the Project has Content languages, or one it lacks
invalid-filter A filter not shaped as one, a path not marked, a value of the wrong kind
invalid-sort A path that can’t be sorted by, or too many
invalid-paging A limit or an offset out of range
invalid-count A count that isn’t true or false
invalid-include An include naming what isn’t a Relation, or too deep
invalid-collection, invalid-id, invalid-query A Collection key, an id, or a query not shaped as one
