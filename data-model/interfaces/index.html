Interfaces

An Interface is the component that edits a Field in the Item view, and shows its value in the List view: an Input, a Dropdown, a WYSIWYG editor, an Image. The Data type says what the Field stores; the Interface says how editors write it. One Data type can be edited by several Interfaces: a string by an Input, a TextArea, a Dropdown, a Colour picker, an Icon picker or an Autocomplete.

Choosing an Interface

Section titled “Choosing an Interface”

A new Field starts from its Interface: Add field opens the picker, which groups them as Text & numbers, Selection, Relational, Presentation and Other, each with the Data types it edits, and searches them by name.

Once added, a Field can change to any other Interface that edits its Data type, on its Interface tab: a text Field written in a TextArea can become Markdown. A Relation’s Interfaces only edit Relations of their kind, and File and Image only Fields that hold Files, so those change only among themselves. An Image URL or a Video key never changes, nor does another Field become one.

Each Interface has its own options. Those of how it looks are on the Interface tab; those that limit its values, on the Validation tab, beside Required, Nullable and Unique. Nexus checks those limits on every write through the API, not only in the Item view.

Text & numbers

Section titled “Text & numbers”

Input

Section titled “Input”

A single-line box for typing text, numbers or identifiers. A CSV list is typed with commas between its entries.

Edits string, text, integer, bigint, decimal, csv, uuid. It’s the default of each.

Option Tab For What it does
Trim spaces Interface string, text Removes spaces at the start and end of what editors type.
Slug Validation string Its values are slugs, which the Input makes of what editors type or paste.
Maximum length Validation string, text The most characters a value may have; at most 255 for a string.
Minimum, Maximum Validation integer, decimal The smallest and largest values allowed.
Decimals Validation decimal How many digits it may have after the decimal point.

Reelhouse’s films’ title and slug are Inputs, and the slug, which names a film in its Preview URL, is a Slug.

Slug

Section titled “Slug”

A slug is lowercase letters and digits, in groups joined by single hyphens: the-thirteenth-lamplighter, never The Thirteenth Lamplighter, the--lamplighter, -lamplighter or the_lamplighter. With Slug on, the Input makes one of what editors write:

  • As they type, it lowercases the text, removes its accents, writes letters such as ß, æ and ø as ss, ae and o, and turns any other character into a hyphen, repeated hyphens into one: typing Película Ñu gives pelicula-nu, and Straße gives strasse. A hyphen at the end stays, so the next word can be typed after it.
  • When they leave the box, it removes the hyphen at the end.
  • What they paste is made a slug the same way.

A value that isn’t a slug is refused with a message saying so, by the Item view and by every write through the Items API, whose refusal says not-a-slug. An empty value is left to Required. It applies to a string Field of a Translations collection as to any other, and a Model snapshot carries it with the Field.

Turning Slug on changes no value stored already: an Item that has a value that isn’t a slug, in its own Fields or in a Translation, keeps it, and can’t be saved in the Item view until it’s fixed.

TextArea

Section titled “TextArea”

A box for text of several lines, which grows as editors write. Edits string, text. Options: Trim spaces; Maximum length (Validation). A person’s biography is one.

Code

Section titled “Code”

Source code with line numbers, highlighted in the language you pick. Edits text, json.

  • Language: Plain text, JSON, XML, HTML, CSS, JavaScript, TypeScript, Java, C#, C++, Python, SQL or YAML. A text Field in JSON is checked to be valid JSON. A json Field is always JSON, written as such, and has no language to pick.
  • Wrap long lines: long lines continue below instead of scrolling sideways.

It’s the default Interface of a json Field.

Markdown

Section titled “Markdown”

Markdown, written with a toolbar for its usual marks. Edits text. Options: Maximum length (Validation). Nexus stores the Markdown as written; whoever reads it renders it.

WYSIWYG

Section titled “WYSIWYG”

Formatted text, written as it reads and stored as HTML. Edits text. Options: none. The films’ translated synopsis and the TV shows’ synopsis are written in it.

Tags

Section titled “Tags”

Free texts editors add one by one, such as keywords, kept in their order as a list. Edits json, csv. Options: none. In a csv Field, no tag may hold a comma.

Amount

Section titled “Amount”

A decimal amount of money in the currency you name, written in each reader’s regional format with the currency’s sign. Edits decimal.

  • Currency: an ISO 4217 currency, EUR unless changed. Amounts take no more decimals than it has: none for yen, two for euros.
  • Minimum, Maximum (Validation).

Autocomplete

Section titled “Autocomplete”

A value picked among those an external URL suggests as editors type. Nexus asks the URL on their behalf, so it needn’t be reachable from their browsers, and stores the value picked as it is, without checking it against the URL later. Edits string, integer.

Option What it does
URL The web address asked for suggestions, answering JSON. {query} in it takes what the editor types; without it, the URL answers the whole list and Nexus searches its labels. Required.
Path to the list Where the list of results is in the answer, such as data.items; empty when the answer is the list.
Path to the value Where each result holds the value to store, such as id. Required.
Path to the label Where each result holds the text editors see, such as name; empty to show the value.
Lookup URL Where Nexus finds the label of a stored value, {value} in it taking the value; it answers that result, a list holding it, or 404. Empty to search for the value as if typed.

For example, https://api.example.com/countries?search={query}, with data as the path to the list, code as the value and name as the label, stores ES and shows “Spain”.

Selection

Section titled “Selection”

Toggle

Section titled “Toggle”

An on/off switch. Edits boolean. Options: none. The languages’ mandatory and default Fields are Toggles.

Date and time

Section titled “Date and time”

A date picker, a time picker or both, by the Field’s Data type. Edits date, time, datetime, timestamp. Options: Include seconds, for all but date. A timestamp is picked in the User’s timezone, the others as they read on any clock; see datetime or timestamp. A person’s born is a date.

Dropdown

Section titled “Dropdown”

One choice, or several, among the options you list. Edits string and integer, one choice, or json, several, kept as a list in the order chosen.

  • Several choices: whether editors pick as many as they like, which makes the Field a json one. It can’t switch while the Collection holds Items.
  • Choices: each with its Value, what Items store, its Text, shown where its Label has none in the UI language, and its Label in other languages, moved up and down to order them.
  • Searchable: adds a search box to the list of choices. Lists of more than 8 choices always have one.

Reelhouse’s films’ certification stores PG, and shows “PG: parental guidance” in English and “PG: con supervisión” in Spanish. Each choice says how many Items use it. Removing one in use, or changing its value, leaves those Items with a value that is no choice any more, which they keep, shown as such, until someone changes it.

Slider

Section titled “Slider”

A whole number picked on a track, from a minimum to a maximum, by steps from the minimum. Edits integer. Options: Minimum, 0 unless changed; Maximum, 100; Step, 1.

Colour

Section titled “Colour”

A colour picked, or written as hex or rgb()/rgba(), such as #7c3aed. Edits string. Options: none. Each Reelhouse genre has a colour.

Icon

Section titled “Icon”

One of the Material Symbols, picked by its name or by what it shows. Edits string, storing the symbol’s name, such as theater_comedy. Options: none. Each Reelhouse genre has an icon.

Relational

Section titled “Relational”

These edit Relations and Files. Choosing one adds a Relation, or a Field that holds Files, with the Field.

Relation picker

Section titled “Relation picker”

Refers to one Item of another Collection, or of its own: the Many to One. It shows that Item by its Collection’s Display template, with buttons to clear it, open it and pick another from the target’s List view. Edits Many to One Fields, whose Data type is the target’s primary key type.

  • Own display template: shows the related Item its own way, by Fields of the related Collection and texts, instead of by its Collection’s Display template.

A season’s tv_show and an episode’s season are Relation pickers.

Related Items

Section titled “Related Items”

The Items a One to Many or a Many to Many links, page by page, with buttons to link more from the target’s List view, create one, open and unlink each, and put them in order when the Relation keeps one. Edits One to Many and Many to Many Fields.

Option What it does
Presentation List, one line per Item by its Display template, or Table, of chosen columns.
Own display template For a list, shows them its own way instead of by their Collection’s Display template.
Columns For a table, what it shows of each Item, in order, up to 20: Fields of the related Collection, Fields reached through its Many to One Relations or of its Translations, by their path, such as season.tv_show.title (see Showing related Items), or the Item by its Display template. The API holds them as { "kind": "field", "key": "season.tv_show.title" } and { "kind": "display" }.
Page size How many show at once, up to 100; empty for the Project settings’, 10 unless changed there.

A film’s genres and cast, and a TV show’s seasons, are Related Items.

Related Items of several Collections

Section titled “Related Items of several Collections”

The Items a Many to Any links, of several Collections, mixed, page by page, each named by its Collection. Edits Many to Any Fields. Options: Presentation, Columns, which may show the Collection of each Item and, of a Field some of its Collections have, show it empty for Items of the others, and Page size. Each Item shows by its own Collection’s Display template. The homepage’s featured films and TV shows show as a table of each one’s Collection and Display template.

Translations

Section titled “Translations”

An Item’s Translations, a tab per Content language, each marked with how far it is translated. Edits Translations Fields.

  • Required languages (Validation): languages this Field must be translated into besides the mandatory ones, which it always must.

File

Section titled “File”

A File uploaded through the Field: its title, name, type and size, with a thumbnail when it’s an image, and buttons to upload one, replace it, download it and clear it. Edits uuid, holding the File’s id.

Option Tab What it does
File folder Interface The File folder its Files land in; none unless chosen.
Largest file Validation The largest File it takes; empty for the Project’s largest upload, which it can’t go above.
Allowed types Validation The MIME types it takes, such as application/pdf, or image/* for every image; empty for any.

Image

Section titled “Image”

A File Field that takes images only, shown by their thumbnails: PNG, JPEG, WebP, GIF, AVIF and SVG. Edits uuid. Options: as File’s, its allowed types being image types. Films’ and TV shows’ posters land in the Posters File folder, people’s photos in Photos. See File and Image Fields.

Presentation

Section titled “Presentation”

These store nothing (their Data type is none): they only show something in the Item view, filled in with the Item’s values as it’s edited.

Notice

Section titled “Notice”

A message for editors, shown in the Item view in their UI language.

  • Message: what it tells editors, as a default text and its Label in other languages.
  • Tone: Information, Success, Warning or Danger, by what it tells.

Button

Section titled “Button”

A button in the Item view that opens a web address in a new tab.

  • Text: what the button says, as a default text and its Label in other languages.
  • Link: the web address it opens.

A Notice’s message and a Button’s text and link fill in the Item’s values with placeholders, between double braces, which their boxes show as chips, by the names of what they fill in. Insert field, at the end of each box, its default text’s and each translation’s, or {{ typed in it, opens the list of what it can insert there:

Placeholder Fills in
{{slug}} A Field of the Item that stores a value.
{{translations.title}} A Field of its Translations, through its Translations Field, in the Content language the Item view reads them in.
{{season.tv_show.title}} A Field of the Item a Many to One Relation holds, and on through that Item’s own, up to 3 Relations on the way, the last maybe a Translations Field.
{{$language}} The code of that Content language.
{{$id}} The Item’s id.

A Button whose link is https://reelhouse.example/{{$language}}/films/{{slug}} would open Paper Comets on the website, in English while the Item view reads its English Translation.

In Insert field, a Many to One is a group to open, as in a Display template: its target’s Fields that store a value, its own Many to One Relations and its Translations Field, searched by every name on the way, the chip named after the whole way, Season › TV show › Title. A Notice on Reelhouse’s episodes saying Episode of {{season.tv_show.title}}, season {{season.number}} would read “Episode of Wexmoor Tide, season 1” in the Item view of an episode of its first season, and follows the season the editor picks, before saving too. Where a Relation on the way holds no Item, the placeholder fills in nothing; a Translation is read in the Content language the Item view reads, with nothing for an Item without one in it.

A placeholder fills in a part of a date Field when it wraps its path in the part’s Field function, typed, as the list doesn’t offer it: a Notice on Reelhouse’s films saying Premiere on {{weekday(released_on)}} reads “Premiere on Friday” for Paper Comets, released on 15 March 2019, its chip named Release date › Weekday. A Notice’s message and a Button’s text write a month and a weekday by name in your UI language, the other parts as numbers; a Button’s link writes each as a number, a month, a day, an hour, a minute and a second with two digits, as a Preview URL does. A timestamp’s parts are read in your Profile’s timezone. A part the Field’s Data type doesn’t have, {{hour(released_on)}} of a date, is refused, and so is a count.

A Field a placeholder names, or a Field or Relation it reaches through, in its Collection or in another, can’t be deleted while it’s there, nor stop storing a value, nor change its Data type to one without a part it fills in.

Other

Section titled “Other”

Repeater

Section titled “Repeater”

An ordered list of Rows, all with the same Repeater fields, kept in a json Field. Edits json. Its options define its Repeater fields; see Repeaters.

Image URL

Section titled “Image URL”

An image Nexus doesn’t hold, on a CDN or the client’s own server, by its URL and a name, shown in the Item view as an Image is. Edits json, as { "url": "…", "name": "…" }. Options: Base URL, which relative URLs are read from, and URL previews, the smaller renditions shown in its place. Films’ still is one. See Image URLs.

Video key

Section titled “Video key”

A video on an external platform, such as YouTube or Vimeo, by its site, its key there and a name, played in the Item view. Edits json, as { "site": "…", "key": "…", "name": "…" }. Options: Video sites, each an identifier, a label and the URL templates of its player and thumbnail. Films’ trailer is one. See Video keys.
