Example: cinema-demo

cinema-demo is the Extension of the Reelhouse demo, in extensions/cinema-demo of Nexus’s repository: one TypeScript file, src/index.ts, compiled with tsc to dist/index.js. It does four things:

  • Its Action handler count-episodes, which Reelhouse’s Action Count episodes runs, counts the episodes of TV shows through their seasons.
  • A before read hook keeps the films not yet released from API users.
  • A before write hook tidies a film’s title.
  • An after write hook logs each film added.

This page reads it from the top; the whole file is at the end.

The model it needs

Section titled “The model it needs”

A films Collection with a title and a release_year; a seasons Collection with a Many to One tv_show to tv_shows, and an episodes Collection with a Many to One season to seasons. Reelhouse’s Model snapshot has them all, and the Action Count episodes of tv_shows, which runs count-episodes · cinema-demo. An Extension names Collections and Fields by their keys, which can’t change once saved: it keeps them in constants.

TV_SHOW_OF_EPISODE is a path through Relations, as filters take it: an episode’s season, then that season’s tv_show.

count-episodes

Section titled “count-episodes”

An Action’s run gives the ids of its Items as text. A filter on a Many to One compares them with the ids its table holds, numbers for Reelhouse’s integer ids:

The handler itself:

  • run.items: the ids of the TV shows it’s run on, one in the Item view, those selected in the List view.
  • For each, a page of one episode, filtered by the episode’s season’s TV show. Only its total is needed: how many episodes pass the filter, which a page of one counts as a page of all would.
  • items reads as the User’s Role allows: it counts the episodes their Role reads, and tells no one of the others. It only reads, so it needs no transaction.
  • When any TV show has none, it’s refused, ExtensionRefusal, which the User sees as It was refused. with its message: The TV show has no episodes., or 1 of the 2 TV shows has no episodes.
  • Otherwise it returns its message, which the User sees under Done., and the Delivery log keeps.

Reelhouse’s TV shows all have episodes: Count episodes run by Marta Quiroga on Wexmoor Tide answers The TV show has 11 episodes.

Keeping unreleased films from API users

Section titled “Keeping unreleased films from API users”

A read hook before every read of films, for API users only, such as Reelhouse’s Website build. It returns a filter the films must pass too: released by a year.

That year is its setting RELEASED_BY, from NEXUS_EXTENSION_CINEMA_DEMO_RELEASED_BY, or this year. One that isn’t a year is a deployment’s mistake, which it logs, rather than refusing every read:

A film added for 2099 is the first of the films by latest release for the admin, while Website build reads 12 films and is answered 404 for it. That’s through the Items API: the Read model, which the website builds from, runs no read hooks.

Tidying a film’s title

Section titled “Tidying a film’s title”

A before hook of creating and updating films. It changes payload where it is:

  • payload holds only what the write changes: an update that leaves the title as it is has none, and the hook does nothing.
  • It’s never null for a creation or an update, only for a deletion, which this hook isn’t registered for; payload && is for the type.
  • The title it writes is validated as the User’s would be: still unique with its release year, as the films’ Unique set says.

" The Saltmarsh Inheritance " is written as "The Saltmarsh Inheritance". The title’s Translations, under translations, are written as they come.

Section titled “Building and deploying it”
