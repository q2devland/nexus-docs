Read hooks

A read hook runs when Items are read: before the read, able to narrow what it finds with a filter, or to refuse it, and after it, able to change what it answers. They run for every caller alike, the web app, the Items API and API users, on four reads, which read tells apart:

  • page: a page of a Collection’s Items, as a List view or GET /api/items/<collection> reads it.
  • one: one Item, by its id, as the Item view or GET /api/items/<collection>/<id> reads it.
  • related: the Items a Relation of an Item links, as GET /api/items/<collection>/<id>/<field> reads them. The Item is found first as reading it alone would: through the before hooks of its own Collection, as one.
  • export: a CSV export.

The History, the Read model and what Extensions read themselves, through items, run none.

Before read hooks

Section titled “Before read hooks”

A before read hook is given read, collection, id for one (null otherwise) and the context of a read. It may return a filter, in the filter language, that the Items must pass too, besides what the read asks:

  • On any of their Fields, through their Relations too, whatever the User’s Role sees of them; not through their Translations, as a read hook’s filter has no Content language to read them in.
  • A page answers only those it keeps, and its total counts only them; but for the Items of every Collection a Many to Any links, whose total counts the links.
  • One Item it keeps out is not found, a 404, as one that doesn’t exist.
  • With several before read hooks, the Items must pass every filter they return.

Reelhouse’s keeps the films not yet released from API users, such as its website’s build, Website build: their release_year must be this year at most, or the year its RELEASED_BY setting says.

It only holds where read hooks run: the Items API. Reelhouse’s website builds from the Read model, which runs no read hooks, so what it publishes is chosen in the Read model instead.

Returning nothing, as it does for Users who sign in, leaves the read as it is. A film added for 2099, The Lighthouse Almanac, is the first of the films by latest release for the admin, but Website build’s page of films doesn’t have it, still counts 12 films, and GET /api/items/films/<its id> answers it 404.

Throwing an ExtensionRefusal refuses the read with a 422, its problem coded extension in the Extension’s own words:

Anything else it throws, or a filter it returns that fails, as one on a Field the Collection lacks, refuses it with a 500 that says no more than An Extension failed, so nothing was read, the error logged under the hook and the Extension.

After read hooks

Section titled “After read hooks”

An after read hook runs once the Items are read, once for each page, each batch of a CSV export, or the one Item, with found too: the Items as answered, with what the read asked of them. It may change their values where they are, or return them changed, one for each, in their order:

It only changes what each Item has, as read: it adds no Item, and values of what an Item didn’t have, a Field not asked for, one the model lacks or the Role doesn’t see, are left out. A hook that returns no Item for each refuses the read, with a 500. Several after read hooks each get the Items as those before them left them.

What an after read hook changes is only what’s answered: nothing is written, and filters and sorting were applied to the Items as saved.

Their context

Section titled “Their context”

A read opens no transaction: a read hook’s items only reads, its files only reads Files, and its db is the database itself. See The hook context.
