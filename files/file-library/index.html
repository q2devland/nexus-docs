File library

The File library is the section listing every File of the Project that your Role may view, whichever Item holds it: Reelhouse’s 46, a poster for each of its 12 films and 4 TV shows and a photo for each of its 30 people. It opens on All files; its panel lists No folder, for the Files of Fields that name no File folder, and each File folder, Reelhouse’s Photos and Posters, as far as your Role may view their Files.

Files come into the File library through the File and Image Fields of Items, never on their own: there’s no uploading here. Under its title, it says how many Files it shows, as the search and filters keep them: 46 files.

Cards or a grid

Section titled “Cards or a grid”

Files show as cards, at first, or as a grid, which Show as grid and Show as cards, in the header, switch between; each browser remembers which you last picked. A card shows the File’s thumbnail, or an icon of its type, its title, its name, and its type, size and dimensions.

The grid shows a File a row, and works as a List view’s does: sorted by its headers, whose menus move and hide columns and add those hidden. Its columns:

Column What it shows
Title Its thumbnail, or an icon of its type, and its title.
Name Its name when uploaded, such as paper-comets.png.
Type Its MIME type, such as image/png.
Size How large it is.
Dimensions An image’s width and height in pixels, Reelhouse’s posters 400 × 600.
Folder Its File folder, or No folder.
Uploaded by, Uploaded on Who uploaded it, or last replaced it, and when.
Used in How many Items hold it.

Without a sort, the newest Files come first; the cards are sorted from Sort by in the header, by any of the grid’s columns, ascending or descending. Both page as the Project settings say List views do, scrolling through every File or a page at a time; see Project settings.

Searching and filtering

Section titled “Searching and filtering”

The search box finds Files whose title, name or type holds what you type, whatever its case and accents: paper-comets finds Paper Comets’ poster, image/svg every SVG.

Filters opens the filters panel, as a List view’s does, testing what’s known of each File: its Title, Name and Type, its Size (bytes), Width (px) and Height (px), when it was Uploaded on, and how many Items it’s Used in (Items). Used in equal to 0 keeps the Files no Item uses, which the clean-up deletes.

A File’s panel

Section titled “A File’s panel”

Pressing a File opens it in a panel along the end of the screen: its title, an image as wide as the panel, with View full screen to see it whole, or else an icon of its type, then its title, its details and the Items that use it. The icons in its header, as your Role allows them:

  • Replace the file: new bytes for the File, keeping its id, in every Item that holds it; see Replacing Files.
  • Download: saves it under its name.
  • Delete the file, while no Item uses it.
  • Close.

Its title, under the image, is changed there with Change the title by a User whose Role may replace the File, for every Item holding it; see Replacing Files. Below it are its name, type, size, an image’s dimensions, its File folder, and when it was uploaded and by whom.

Where a File is used

Section titled “Where a File is used”

Used in lists the Items that hold the File, each by its Collection’s Display template, with its Collection and the Field it’s held in: Paper Comets’ poster is used by Paper Comets (2019), Films · Poster. A File held by one of an Item’s links, through a File or Image Field of a Junction collection, is used by the Item whose link it is.

An Item listed opens in a panel of its own over the File’s, to read or edit as in the Item view; what you change there, such as the File it holds, shows in the File library once it closes.

The list leaves out the Items you can’t see, of Collections your Role can’t read or through Fields hidden from it; the number on the File, and in the grid, counts them all.

Deleting a File

Section titled “Deleting a File”

Delete the file, once confirmed, deletes it and its bytes for good. A File an Item uses can’t be deleted, which its panel says: free it from every Item first, by removing it from the Field holding it, or deleting the Item. A File no Item uses is deleted anyway by the next clean-up a day after its upload, as its panel says; see Unused Files.

Who sees what

Section titled “Who sees what”

Your Role’s File folder permissions decide which Files the File library shows: those of each File folder, and those of no folder, that it may view, and whether it may replace and delete them. A File folder whose Files it can’t view is left out of the panel; an admin sees every File and does everything. Reelhouse’s Editors view, replace and delete its posters and photos; its Translators and Viewers only view them; and only its admins see No folder, which is empty.

What the File library leaves out still shows where it’s held: an Item you may read shows the Files it holds, whatever their File folder.
