Glossary

Every term Nexus uses, as this site uses it, with the page that covers it. Terms are capitalised wherever they appear, so that a Collection, an Item or a Role always means just this.

Platform

Section titled “Platform”

Nexus

Section titled “Nexus”

The product: the web app, the API and the packages that come with them, built by q2devland and deployed for its clients, one Project each.

Project

Section titled “Project”

One deployment of Nexus, with its own database, configuration, Users and branding. There is one Project per deployment, never several sharing one. See What is Nexus.

Project settings

Section titled “Project settings”

What admins configure for the whole Project outside its data model: its branding (name, logo, main colour, typography and login background), the Content languages collection, how List views page through their Items, how many related Items the Item view shows at once, and whether every write of an Item must say who makes it. See Project settings.

Data model

Section titled “Data model”

Collection

Section titled “Collection”

A type of content that admins define in the browser, with its own Fields and Relations, such as Reelhouse’s films. It may show an icon, in a colour, wherever it’s listed, and may be a singleton, holding a single Item. See Collections.

Collection key

Section titled “Collection key”

The snake_case identifier of a Collection, such as films or tv_shows, which names it in the API and never changes. Shown wherever the Collection has no Label in the User’s UI language.

Field

Section titled “Field”

An attribute of a Collection, such as a film’s title, identified by its key, with a Data type and an Interface. See Fields.

System field

Section titled “System field”

One of the Fields every Collection has: id, created_on, created_by, updated_on and updated_by, who created and last changed an Item, and when. They can’t be deleted or changed, but can be given Labels, placed anywhere in the Item view or hidden from it, and shown as List view columns. See Fields.

Label

Section titled “Label”

The text shown for a model element instead of its key: a Collection’s or Field’s name, a description, a placeholder, a Field group’s name, a Dropdown choice, a notice or a confirmation; or a Folder’s or File folder’s, instead of its name. It has one value per language, of any of the ISO 639-1 languages, and shows in the User’s UI language. Without one in that language, Nexus shows the key as words (release_year reads “Release year”), except in the Data model section, which shows the key as it is.

Data type

Section titled “Data type”

What a Field stores: a string, a text, an integer, a decimal, a boolean, a date, a datetime, a timestamp, json, csv, a uuid… independently of how it’s edited. A datetime reads the same on any clock; a timestamp is an instant, shown in each User’s timezone. A Field of Data type none stores nothing and only shows something in the Item view, such as a Notice or a Button. See Data types.

Field function

Section titled “Field function”

What’s read of a Field instead of its value, to filter and sort Items by, and, a part, to show as a column, in a Display template and in a placeholder: a part of a date, datetime, timestamp or time, such as its year, its month or its weekday, a timestamp’s in the timezone of whoever reads or writes it, or the count of a many-relation’s links, all of them, to filter by and to test in a Field condition alone. See Field functions.

Interface

Section titled “Interface”

What edits a Field in the Item view, such as an Input, a Slider, a Toggle or a WYSIWYG. One Data type can be edited by several Interfaces. See Interfaces.

Repeater

Section titled “Repeater”

An Interface that edits a json Field as an ordered list of Rows, all with the same Repeater fields, such as an episode’s release_dates, one Row per country. See Repeaters.

Repeater field

Section titled “Repeater field”

One of the children a Repeater defines, which every Row has a value for, with its own key, Data type, Interface, Labels, placeholder, default and whether it’s required. It isn’t a Field: it has no permissions or conditions of its own.

Row

Section titled “Row”

One element of a Repeater’s list, with a value for each of its Repeater fields.

Image URL

Section titled “Image URL”

An Interface that edits a json Field as an image Nexus doesn’t hold: its URL, absolute or relative to the Field’s base URL, and its name, taken from the URL’s last segment when none is given, such as a film’s still. See Image URLs.

URL preview

Section titled “URL preview”

One of the smaller renditions of an Image URL’s image that its Field lists, by the address that returns it, with {{path}} or {{filename}} standing for the image’s, and the width it returns. The CMS shows the one that fits; nothing else uses them.

Video key

Section titled “Video key”

An Interface that edits a json Field as a video on an external platform: one of the Field’s Video sites, the video’s key on it and a name, such as a film’s trailer. The CMS plays it; the API answers { site, key, name }, never the player’s address. See Video keys.

Video site

Section titled “Video site”

One of the platforms a Video key Field plays from: its identifier, such as youtube, an optional label, and the URL templates of its player and thumbnail, with {{key}} for the video’s key. Never iframe HTML.

Unique set

Section titled “Unique set”

Two or more Fields of a Collection whose values no two of its Items may share all at once, such as a film’s title and release_year. An Item lacking a value in any of them clashes with none. See Collections.

Field group

Section titled “Field group”

A named section of the Item view holding Fields, which editors collapse and expand. It may show an icon, in a colour, start collapsed, be hidden with its Fields, and have conditions of its own. See Field layout.

Field width

Section titled “Field width”

How much of a row of the Item view a Field takes: full, the default; half, sharing the row with the next Field when it takes half too; or half alone, leaving the other half empty. On narrow screens, Fields stack. See Field layout.

Field condition

Section titled “Field condition”

A named rule that makes a Field hidden, read only or required, or the opposite, when tests on other Fields of the same Item, or on the User’s Role, hold, such as hiding a TV show’s end_year until its status is Ended. A Field’s conditions are ordered, and for each state the last one that holds wins. See Field conditions.

Relation

Section titled “Relation”

A link between the Items of Collections, through a Field: Many to One, One to Many (the other side of a Many to One), Many to Many, Many to Any (to Items of several Collections) or Translations. The Items a One to Many, Many to Many or Many to Any Field relates to an Item are its links, which editors link and unlink. See Relations.

Junction collection

Section titled “Junction collection”

The Collection holding the links of a Many to Many or a Many to Any, one Item per link, created and deleted with its Relation, such as films_genres. Admins may give it Fields of their own, which describe each link, as films_cast’s character and billing_order do. It’s hidden at first. See Junction collections.

Display template

Section titled “Display template”

The mix of Fields and text that represents an Item of a Collection wherever it appears through a Relation, such as a film’s title (year(released_on)), the year of its release date, which reads “Paper Comets (2019)”. Every Collection has one. See Collections.

Searchable field

Section titled “Searchable field”

A text or numeric Field that a List view’s search looks in, of the Collection itself or of its Translations, in the Content language shown. See List views.

Folder

Section titled “Folder”

A node of the Navigation tree that groups Collections and other Folders, with a name, Labels, an icon and a colour, such as Reelhouse’s Catalogue. It holds no content.

Navigation tree

Section titled “Navigation tree”

The tree of Folders and Collections, as deep as needed, shown in the panel of the Content and Data model sections, where a Collection may also hang under another Collection. See Navigation tree.

Model snapshot

Section titled “Model snapshot”

A file holding a Project’s whole model: its Collections, Fields, Relations, Navigation tree, File folders, Roles, Actions, Webhooks and Content languages collection, without Items, Users or secrets. Another Project applies it, after reviewing what it changes, all of it or none, and its model becomes the snapshot’s. See Model snapshots.

Model revision

Section titled “Model revision”

A number that changes whenever something a client reads about the model may have changed: a Collection, Field, Field group or the Navigation tree, a Model snapshot applied, a Content language, a Role or its permissions, or the Role of a User. Every answer of the API tells it, so a client that keeps what it read of the model knows when to read it again. See Project settings.

Preview URL

Section titled “Preview URL”

The address on a website where a Collection’s Items are previewed, framed in a side panel of the Item view, with placeholders for an Item’s Field values, its Translations’ and the Content language previewed. See Preview URLs.

Content

Section titled “Content”

Item

Section titled “Item”

A single piece of content of a Collection, such as the film Paper Comets.

List view

Section titled “List view”

The grid of a Collection’s Items, where they’re searched, filtered, sorted and exported. See List views.

Saved view

Section titled “Saved view”

A named List view, with its icon, columns, sort, search, filters and page size, personal to whoever saved it unless an admin shares it with Roles, whose Users may use it but not change it. Listed under its Collection in the Navigation tree. See Saved views.

Item view

Section titled “Item view”

The screen that shows and edits a single Item. See Item view.

History

Section titled “History”

The record of every change to the Items of a Collection that keeps it: who created, changed or deleted an Item, linked or unlinked Items, changed its Translations or retitled or replaced a File it holds, when, and its values before and after. It’s written by the database itself, so changes made outside Nexus are recorded too, and kept for the Collection’s retention, if it has one. It can be read, never restored. See History.

Languages

Section titled “Languages”

UI language

Section titled “UI language”

The language a User picks for Nexus in their Profile. Labels show in it, and Nexus’s own texts too where they’re translated into it (English, Spanish and Catalan), else in English. It has nothing to do with Content languages.

Content languages collection

Section titled “Content languages collection”

The Collection that the Project settings designate as holding the Content languages, such as Reelhouse’s languages. None exists at first, and until one is designated no Translations can be created. See Project settings.

Content language

Section titled “Content language”

An Item of the Content languages collection, identified by its code, such as en. A Project may have none.

Translations

Section titled “Translations”

A Relation from a Collection to its Translations collection, holding the Fields that differ per Content language, such as a film’s title and synopsis. See Translations.

Translations collection

Section titled “Translations collection”

The Collection holding one Item per parent Item and Content language, such as films_translations, configured like any other Collection.

Access

Section titled “Access”

User

Section titled “User”

A person who signs in to the Project. A User must exist in the Project before signing in: invited until they accept their Invitation, then active, or inactive once an admin deactivates them, which signs them out and keeps them from signing in while what they wrote stays theirs. See Users.

Identity provider

Section titled “Identity provider”

A way of signing in that the deployment enables, under a name of its choosing, of one kind, such as Google or Microsoft. A Project may have several, even of the same kind. See Identity providers.

Identity

Section titled “Identity”

A link between a User and one account at an Identity provider. A User may have several, one per Identity provider they sign in with. See How sign-in works.

Invitation

Section titled “Invitation”

An expiring link sent by email that lets a User added beforehand, with their Role, sign in for the first time, with an account of the email it was sent to; any other account is refused. See Invitations.

API user

Section titled “API user”

A User that isn’t a person: another system that calls the API with API tokens, and never signs in. See API users and tokens.

API token

Section titled “API token”

A named secret of an API user, which may expire, and whose value is shown only once. See API users and tokens.

Profile

Section titled “Profile”

A User’s own page, opened from their avatar: their account, their preferences (UI language, theme, timezone and regional format) and signing out. See Profile.

Role

Section titled “Role”

The set of permissions given to a User; every User has exactly one. See Roles.

Admin role

Section titled “Admin role”

A Role that may do everything, and the only one that may change the data model.

Collection permission

Section titled “Collection permission”

What a Role may do with the Items of a Collection: read, create, update or delete them; anything but reading needs reading too. A Collection a Role can’t read is left out of its Users’ Content section. See Collection permissions.

Field permission

Section titled “Field permission”

How a Role sees a Field: hidden, read or write; write unless set otherwise. A Relation Field leading to a Collection the Role can’t read is hidden from it, and an Item’s id is always seen. See Field permissions.

File folder permission

Section titled “File folder permission”

What a Role may do in the File library with the Files of a File folder, or of none: view, replace or delete them; replacing or deleting needs viewing too. None is granted until given. See File folder permissions.

Read model

Section titled “Read model”

Write model

Section titled “Write model”

Where the CMS reads and writes Items: the Collections themselves, with their Relations and Translations.

Read model

Section titled “Read model”

A copy of the Items of the Collections that keep one, for clients outside the CMS to read, rebuilt shortly after each change, whoever made it. Each Item appears once, with its chosen Fields, its Relations, which a client may load in place, and its Translations per Content language. It has no publishing state of its own, and the CMS never reads it. See Read model.

Automation

Section titled “Automation”

Webhook

Section titled “Webhook”

A call Nexus makes to an external URL after Items of chosen Collections are created, updated or deleted. It carries the Item’s id, never the Item, and is retried when it fails. See Webhooks.

Action

Section titled “Action”

A button of chosen Collections, in their Item view, on a selection of their List view, or both, that calls an external URL or runs an Extension’s Action handler, once for all the Items it’s run on, optionally after a confirmation and a few values entered by the User. A primary Action shows as a button of its own. See Actions.

Delivery log

Section titled “Delivery log”

The record of every call made by a Webhook or an Action, and every run of an Action handler, with its outcome. See Delivery log.

Extension

Section titled “Extension”

Custom code deployed with a Project that runs around Nexus’s own reads and writes of Items, through its Extension hooks, or when an Action runs it, through its Action handlers. Admins enable or disable each one in Settings. See Extensions.

Extension hook

Section titled “Extension hook”

A point where an Extension runs around a read or a write of Items: before or after it, and, for a write, as part of it, able to change it or cancel it. See Write hooks and Read hooks.

Action handler

Section titled “Action handler”

A named entry point an Extension offers for Actions to run, with the Items they’re run on and the values entered. An Action whose handler is missing, or whose Extension is disabled, can’t be run. See Action handlers.

Files

Section titled “Files”

File

Section titled “File”

An uploaded file and what’s known about it: its name, its title (at first its name without its extension), its type and size, and an image’s dimensions. Nexus shows it by its title. Files only come in through the File and Image Fields of Items, and those no Item holds any longer are cleaned up. See File and Image Fields.

File library

Section titled “File library”

The section listing every File of the Project that the User’s Role may view, all together or per File folder, where Files are searched, previewed, downloaded, retitled, replaced and, once no Item uses them, deleted. See File library.

File folder

Section titled “File folder”

A grouping of Files, one level deep, with a name, Labels, and optionally an icon and a colour, such as Reelhouse’s Posters. A File or Image Field may name one, and the Files uploaded through it land there. See File folders.
