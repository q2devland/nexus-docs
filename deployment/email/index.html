Email

Nexus sends one kind of email: Invitations, when an admin invites people and when they send one again. It sends them through an SMTP server that the deployment names, any that lets it send from the Project’s address: the organisation’s own, or a service that sends mail for applications.

NEXUS_SMTP_URL

Section titled “NEXUS_SMTP_URL”

The server, as a URL, with its user and password in it if it needs them:

URL How
smtps://user:password@host:465 TLS from the start. Port 465 unless one is given.
smtp://user:password@host:587 Upgraded to TLS when the server offers it, with STARTTLS. Port 587 unless one is given.
smtp://host:25 Without a user, for a relay that knows the machine.

Special characters of the user and the password are percent-encoded, such as %40 for @ when the user is an email: smtps://cms%40reelhouse.example:…@smtp.reelhouse.example. The URL holds the password: keep it with the deployment’s other secrets.

NEXUS_SMTP_FROM

Section titled “NEXUS_SMTP_FROM”

The address Invitations come from, alone, cms@reelhouse.example, or with a name people see, Reelhouse <cms@reelhouse.example>. It’s required with NEXUS_SMTP_URL, and must be one the server lets Nexus send from: most services want its domain verified, with its SPF and DKIM records, before they deliver mail from it. Nexus starts without checking either: the first Invitation does.

When an Invitation can’t be sent

Section titled “When an Invitation can’t be sent”

Nexus waits for the server to take each Invitation: up to 10 seconds to connect and be greeted, and 30 seconds of silence once connected. An Invitation the server doesn’t take isn’t made: the Invite people dialog keeps its email, saying that the Invitation could not be emailed; try again later, while the others are sent. Nexus’s log says why, such as the server refusing the password:

Once the server has taken it, delivering it is the server’s job: a message it bounces later, as no such mailbox exists, goes back to NEXUS_SMTP_FROM’s address, not to Nexus.

Without email

Section titled “Without email”

Without NEXUS_SMTP_URL, Nexus runs as ever, but no Invitation can be sent: inviting people, or sending an Invitation again, is refused, saying that no SMTP server is configured to email Invitations. Admins add Users instead, and tell them the Project’s address themselves.

Trying it

Section titled “Trying it”

A mailbox for development takes whatever it’s sent and shows it, rather than delivering it: Mailpit, say, which shows each Invitation rendered, at http://localhost:8025:

host.docker.internal is the host, from Nexus’s container: on Linux, give it --add-host host.docker.internal:host-gateway, or run Mailpit in the same Compose project and name it, smtp://mailpit:1025.

How long an Invitation’s link works is NEXUS_INVITATION_LIFETIME, 7 days unless set; see Invitations.
